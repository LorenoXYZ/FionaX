# Trade Price Rational Inspector

Paste an array of Horizon trade objects or a Horizon `_embedded.records` page, up to 100 rows and 256,000 characters. The tool is entirely offline: it makes no network or wallet requests, and Reset discards the pasted JSON from component state. Input is never logged or persisted.

Supported records are orderbook trades (`trade_type: "orderbook"` or older records without a trade type) with native or complete `credit_alphanum4`/`credit_alphanum12` identities. Liquidity pool trade prices are unsupported. Each row needs a string trade `id` in `operation-id-index` form, `base_amount`, `counter_amount`, `base_is_seller`, and complete base/counter asset fields. `price: {n,d}` is optional evidence; an absent price produces an incomplete row. Optional base/counter account identities are validated and displayed. Other Horizon metadata is ignored. Amounts are exact decimal strings of at most seven places and at most signed 64-bit stroops. Rational parts are positive signed 64-bit integers supplied as strings or safe JSON integers. Issuer and account addresses are checked with Stellar SDK StrKey; issued assets also use SDK Asset validation.

Horizon reports trade `price` as counter units per base unit regardless of `base_is_seller`; a false flag changes which asset the base side sold, and the seller's bought-per-sold display is the reciprocal. For base B and counter C in stroops, the tool computes `C*d - B*n` using BigInt. Exact zero is an exact match. Absolute difference at most `d+n` is within a conservative bound of one stroop of rounding in each displayed quantity. Above that bound is outside rounding. This is a compatibility check, not proof of an offer or a ledger replay. Zero quantities or missing price cannot establish a ratio; malformed rows remain visible as gaps while other rows are inspected.

The source is user-pasted Horizon JSON and is not authenticated. No automatic pagination, RPC, request, XDR decode or pool-specific price model is supported. This tool cannot establish network provenance or execution semantics beyond the supplied fields.
